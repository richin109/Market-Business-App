## Feature 15.1 — Market Planning and Load Lists
- [ ] Feature complete
- [ ] Extend MVP 2 ordered plan/one target per product into recipe/shopping UI. Select saved markets; reject free text/duplicate IDs; reuse plan identity.
- [ ] For each selected market occurrence, collect weekday, local start time, local end time, and planned date. Default the date to the next occurrence of the selected weekday in `business_timezone`; let the user change the date/time for this plan only without changing the saved market or other plans.
- [ ] Let the user select Square products by Variation ID and edit the set-level shopping/production target; this is the same MVP 2 target, never a stock input (D-53). A recipe-made product uses its recipe effective on the planned production date and shows ingredient/supply needs; a direct-resale product uses its canonical purchased item instead. Missing sourcing is a visible setup blocker; details are read-only here and managed by Capability 4.
- [ ] Provide a Market Load List for each selected market occurrence using its saved Market ID; show desired per-market target, notes, and prep status. Targets may distribute a shopping estimate but never reserve or create stock; confirmed made quantities and approved receipt purchases are allocated/ transferred exactly once across the ordered market set (D-47/D-53).
- [ ] Save lists by market/date and allow copying a prior list while editing quantities without duplicating market identities.
- [ ] Derive each list item's editable planned `Perishable By` estimate from the item's remembered Shelf Life applied to the planned acquisition instant (falling back to list-item creation time); leave it blank for `never` items and preserve explicit list-only estimates when copying lists. A manual list-date edit does not override a purchased or produced lot's authoritative `Perishable By` under D-35; changing stock expiry requires the audited item/recipe Shelf Life edit and open-lot recomputation/restatement path. An item without Shelf Life cannot be imported or persisted as stock, so it cannot enter a shopping list.

## Feature 15.2 — Store-Grouped Shopping Lists
- [ ] Feature complete
- [ ] Calculate ingredient/supply needs from targets, recipes, units, waste; aggregate shared inputs and expected waste. Show missing recipes/incompatible units; never omit silently.
- [ ] Generate one combined shopping requirement for the complete ordered market set, then provide store-grouped lists. Show which market/product targets created each ingredient requirement without multiplying a shared ingredient incorrectly.
- [ ] Subtract available ingredient and supply balances at the planned prep instant, including prior accepted sales/usage and approved movements, from recipe needs; present estimates separately from actual purchases. Planned estimates do not post inventory movements or accrue waste.
- [ ] In MVP 4, read expected balances only through D-51/D-53 approved receipts, made events, recipe usage, Square lines, transfers, and dispositions; targets stay outside the ledger and allocations are not subtracted twice. As-of availability excludes lots at/after `Perishable By` even if the MVP 6 waste job has not yet posted, and labels such lots `EXPIRY_POSTING_PENDING` for inventory/valuation review rather than treating read-time exclusion as a posted loss. `never` items use calculated balance unless audited override exists. MVP 6 posts idempotent waste and versioned weekly closes from these same source lots; no physical counts or parallel balance (SL-003/SL-004).
- [ ] Group requirements by the preferred or selected canonical store from the Capability 2.7 registry, using each store's display name; allow manual item additions, quantity adjustments, and store reassignment. Grouped alias spellings must appear as one store list, and a rename must not split or duplicate a list.
- [ ] Show net-to-buy in the item base unit and, when a remembered pack size and conversion exist for the selected store, as whole packages rounded up (for example 2.25 lb strawberries → 3 × 1 pint). Use the Capability 4.9 conversions; flag items with no conversion path rather than guessing.
- [ ] Include item, quantity/unit, Shelf Life and derived `Perishable By`, optional estimated unit/line cost, last-purchase location, and Product URL where available. Provide a print-friendly page/PDF per store; keep store purchase lists separate from Market Load Lists.
- [ ] Finalize one immutable grouped-list version; require explicit recipient confirmation for one keyed WhatsApp batch. Validate text/templates; track send separately; keep print/export. Changes require new version/explicit send (D-53).
- [ ] Marking items purchased or finalizing a list does not create a purchase. Actual purchased quantity and cost come from an approved receipt line linked to that list; manual purchase entry is available only for a purchase with no receipt, with its own audited source and no duplicate posting if a receipt later arrives. Targets and list checkboxes never become actual purchase facts (D-53).
- [ ] When an OCR-reviewed receipt line also fulfills a shopping-list item, link the list to that existing approved purchase occurrence instead of creating a manual duplicate. A second source PDF for the same order adds no quantity unless its distinct line was reviewed and approved; uncertain weights, package sizes, or units remain drafts rather than inventory inputs (RM-022).

## Feature 15.3 — Confirmed Prep Posting
- [ ] Feature complete
- [ ] The screen records actual `Made N` per recipe-made Variation ID, separate from target. Under D-64 it is the total for that date; re-entry corrects, never adds. Confirmation calls Capability 5's production service, which retains recipe version and atomically posts output/input/supply/waste-remainder through Capability 6; Capability 15 writes no production/stock ledger. Direct resale uses approved receipt quantity, no made event. Corrections append linked adjustments; never rewrite or resend list/WhatsApp (D-52/53/64).
- [ ] Capability 5's shared production service is an MVP 4 prerequisite. Test retry/concurrency/rollback/correction and MVP 5 manual production against one event identity/movement set.
- [ ] Apply each recipe input's waste percentage and carry discrete-unit fractions forward across events/weeks until a whole waste unit is reached; fractional-capable units post exact waste quantities. Corrections reverse/recompute affected movements and remainders idempotently.
- [ ] Associate all movements with the market visit/date and stamp each resulting lot's `Perishable By`: purchased lots from the item Shelf Life and acquisition instant; recipe-produced lots, including consumed ingredients and supplies such as packaging, from the recipe output Shelf Life and production timestamp. A supply marked `never` inherits the recipe lot's expiry once consumed into that lot, while unused supply stock keeps its own Shelf Life. Unconfirmed plans have no effect on inventory, production, sales, or profit.
